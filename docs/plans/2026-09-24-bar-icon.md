# Bar icon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A button in the Omarchy bar that toggles the Omascape overview. It lands right after
the workspaces widget by default, and the shell owns where it sits after that.

**Architecture:** Omascape declares the shell's `bar-widget` kind next to `overlay`. A root-level
`BarWidget.qml` extends the host's `qs.Ui` `BarWidget` and wraps a `WidgetButton` whose left click
runs the same `omarchy-shell shell toggle` command as SUPER+TAB. Placement lives in the shell's
`shell.json` only. Design: `docs/specs/2026-09-24-bar-icon-design.md`. Record:
`lore/knowledge/adrs/0011-bar-icon-surface.md`.

**Tech Stack:** QML (Qt 6.9 floor, ADR-0004), the Omarchy shell's `qs.Ui` module, qmltestrunner
offscreen fixtures, bash + python3 test entry points.

**Worktree:** `/home/daniel/Source/omascape/.claude/worktrees/bar-icon`, branch `feat/bar-icon`
(off `dev`). All commands run from there. PR targets `dev`, never `main`.

## Facts the tasks rely on (read from the host, 2026-09-24)

- `/usr/share/omarchy/shell/Ui/BarWidget.qml` is an `Item` with `property QtObject bar`,
  `property string moduleName`, `property var settings: ({})`, `readonly property bool vertical`,
  `readonly property int barSize` and `function setting(name, fallback)`. `setting` returns
  `fallback` only for `undefined`/`null`, so an empty string comes back as `""`.
- `/usr/share/omarchy/shell/Ui/WidgetButton.qml` declares `property var bar`,
  `property string text`, `property string fontFamily`, `property real horizontalMargin`,
  `property string tooltipText` and `signal pressed(int button)`. Its `MouseArea` (line 95) accepts
  Left, Right and Middle buttons. Its `onClicked` calls `triggerPress(mouse.button)`, which calls
  `bar.hideTooltip(root)` and then emits `pressed(button)`.
- `plugins/menu/BarWidget.qml` is a file named `BarWidget.qml` whose root type is the host's
  `BarWidget`. It loads in production, so the explicit `import qs.Ui` wins over the file's own
  implicit directory import. Our file relies on the same resolution. **The fixture must reproduce
  it: keep the file name `BarWidget.qml` inside its own directory. Do not rename it.**

### Task 1: Stub `qs.Ui` module and fixture wiring (shared test infrastructure — highest stakes)

Every later UI assertion runs against these stubs, so a stub that is healthy for the wrong reason
makes the whole suite meaningless.

**What the fixture must reproduce:**
1. The production `BarWidget.qml`, **byte for byte and under that file name**, loaded through
   `import qs.Ui`. The name resolution in the facts above is then exercised, not bypassed.
2. The click path: a real mouse click on the button area reaches `pressed(int button)` with the
   clicked button, through `triggerPress`, the way the host's `MouseArea.onClicked` does.
3. `setting()` semantics exactly as the host defines them. An empty string is **not** a fallback
   case.

**What the environment cannot supply:** the real `qs.Ui` (it needs `qs.Commons`, `Style`, `Color`
and a running bar). The stubs declare only what `BarWidget.qml` uses. Task 4's drift guard is what
ties them to the host, and CI cannot run it. The fixture comments must say so.

**Must not collapse:** the host's base `BarWidget` and our `BarWidget.qml` are two different types
with the same name. If the fixture renamed ours, a self-instantiation bug ("BarWidget is
instantiated recursively") would pass here and break in production.

// The click path mirrors the host: MouseArea (Left|Right|Middle) → onClicked → triggerPress →
// pressed(button). See the note in BarWidget.qml about drift.

    property var bar: null
    property string text: ""
    property string fontFamily: "sans-serif"

    implicitWidth: 28
    implicitHeight: 26

        root.pressed(button)

        anchors.fill: parent
        acceptedButtons: Qt.LeftButton | Qt.RightButton | Qt.MiddleButton

}

        name: "BarWidget"
        when: windowShown

        readonly property string toggleCmd: "omarchy-shell shell toggle se.mindfulstack.omascape"

            fakeBar.runs = []
            var w = createTemporaryObject(widgetC, host, settings === undefined ? {} : { settings: settings })
            verify(w, "BarWidget.qml instantiates (no recursive self-instantiation)")
            return w

        function button(w) { return findChild(w, "omascapeBarButton") }

        // Catches: wrong or missing command, wrong plugin id, press not wired.
        function test_left_click_toggles_once() {
            var w = make()
            mouseClick(button(w), 5, 5, Qt.LeftButton)
            compare(fakeBar.runs.length, 1)
            compare(fakeBar.runs[0], toggleCmd)
        }
        // Catches: the button filter missing, so every button toggles.
        function test_other_buttons_do_nothing() {
            var w = make()

            mouseClick(button(w), 5, 5, Qt.MiddleButton)
            compare(fakeBar.runs.length, 0)

        function test_no_bar_no_run() {
            failOnWarning(/TypeError/)

        // from the component.
        function test_default_glyph() {

        // Catches: a glyph that is read once and never re-evaluated. The host applies
        // `omarchy bar set` to a running widget by REPLACING `settings` (Bar.qml).
        function test_icon_setting_is_live() {
            var w = make()

            compare(button(w).text, "Y")

        // Catches: the per-entry override not being read.

            compare(button(make({ icon: "X" })).text, "X")

        // Catches: the naive `setting("icon", default)`, which returns "" and renders nothing.
        function test_empty_or_bad_icon_falls_back() {

            compare(make().moduleName, "se.mindfulstack.omascape")

### Task 2: `BarWidget.qml`

**Files:**
- Create: `BarWidget.qml` (repo root)

- [ ] **Step 1: Write the widget**

```qml
import QtQuick
import qs.Ui

// Omascape's bar button (docs/specs/2026-09-24-bar-icon-design.md, ADR-0011). It does exactly
// what the SUPER+TAB bind does, through the same command, so both routes run the overlay's one
// open() path (ADR-0008). Static on purpose: no state, no timers, no compositor calls, so an
// always-visible icon keeps "nothing runs until you summon it" true. Where it sits is the
// shell's business (shell.json bar.layout); nothing here reads or writes it.
BarWidget {
    id: root
    moduleName: "se.mindfulstack.omascape"

    // nf-md-view_grid. `omarchy bar set se.mindfulstack.omascape icon <glyph>` overrides it; an
    // empty or non-string value falls back, because the host's setting() returns "" as-is.
    readonly property string defaultGlyph: "\u{F0570}"
    readonly property string glyph: {
        var v = root.setting("icon", "")
        return (typeof v === "string" && v !== "") ? v : defaultGlyph
    }

    implicitWidth: button.implicitWidth
    implicitHeight: button.implicitHeight

    WidgetButton {
        id: button
        objectName: "omascapeBarButton"
        anchors.fill: parent
        bar: root.bar
        text: root.glyph
        tooltipText: "Workspace overview"
        horizontalMargin: 7.5
        onPressed: function(button) {
            if (!root.bar || button !== Qt.LeftButton) return
            root.bar.run("omarchy-shell shell toggle se.mindfulstack.omascape")
        }
    }
}
```
Properties (ADR-0004): no Qt 6.10+ API and no reserved-word identifiers. The handler's parameter
is `button`, which is not reserved. `\u{…}` code-point escapes are ES2015 and are supported by
Qt 6.9's V4. CI on 6.9 is what proves it, not the local 6.11 run.

### Task 4: Stub drift guard

**Files:**
- Create: `tests/bar-widget-api.sh`

- [ ] **Step 1: Write the guard**

```bash
#!/usr/bin/env bash
set -euo pipefail
# The qs.Ui stubs (tests/ui/stubs/qs/Ui) must not promise a member the real shell no longer has:
# if Omarchy renames WidgetButton.pressed or BarWidget.setting, the UI suite would stay green
# while the real button breaks. Every `property`, `signal` and `function` name declared in a stub
# must still be declared in the host file of the same name.
# Local only: CI has no Omarchy shell, so there this prints SKIP and checks nothing (ADR-0003: a
# SKIP is not a pass; the PR says so).
root=$(cd "$(dirname "$0")/.." && pwd)
host=${OMARCHY_SHELL_UI:-/usr/share/omarchy/shell/Ui}
if [[ ! -d $host ]]; then
    echo "SKIP: bar-widget-api.sh — no Omarchy shell at $host; stub drift unchecked"
    exit 0
fi
fail=0
for stub in "$root"/tests/ui/stubs/qs/Ui/*.qml; do
    name=$(basename "$stub")
    real="$host/$name"
    [[ -f $real ]] || { echo "FAIL: host has no $name"; fail=1; continue; }
    while read -r kind member; do
        if ! grep -qE "^[[:space:]]*(readonly[[:space:]]+)?${kind}[[:space:]]+([A-Za-z]+[[:space:]]+)?${member}[[:space:](:]" "$real"; then
            echo "FAIL: $name: host no longer declares $kind $member"; fail=1
        fi
    done < <(sed -nE 's/^[[:space:]]*(readonly[[:space:]]+)?(property)[[:space:]]+[A-Za-z]+[[:space:]]+([A-Za-z_]+).*/\2 \3/p;
                      s/^[[:space:]]*(signal|function)[[:space:]]+([A-Za-z_]+).*/\1 \2/p' "$stub")
done
(( fail == 0 )) && echo "bar-widget-api.sh: ok"
exit $fail
```
Add `bash "$(dirname "$0")/bar-widget-api.sh"` to `tests/run.sh` after `manifest.sh`.

Change the glyph with `omarchy bar set se.mindfulstack.omascape icon 󰍺` (any Nerd Font glyph).

`omarchy plugin list` reports Omascape as `enabled` only while the button is on the bar. In the
setups below that have no button, it shows `disabled` even though the overview is loaded and
SUPER+TAB works.

**Removing the button disables Omascape.** The shell treats the bar entry as the plugin being
enabled, so `omarchy plugin disable se.mindfulstack.omascape` (or removing the button) also
unloads the overview: SUPER+TAB stops working, and during a screen share the red reminder frame
goes away. Armed workspaces stay blanked in the share either way, because that protection lives
in Hyprland, not in the overview. Re-enable to get everything back.

**Want Omascape without the button?** Add `{ "id": "se.mindfulstack.omascape" }` to the
`plugins` list in `~/.config/omarchy/shell.json`, then run `omarchy plugin disable
se.mindfulstack.omascape` once. That removes only the button, and the overview stays, though
`omarchy plugin list` now shows `disabled`. To disable Omascape entirely from that state, run
the disable command a second time.
